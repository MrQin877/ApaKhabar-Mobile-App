Limits and behavior
- Shared server-enforced 60-second cooldown and five requests per user/phone per calendar day, resetting at backend-local midnight. Failed delivery attempts count, matching the existing limiter. HTTP 429 returns retry information; the app asks users to try again tomorrow after the daily limit.
- A valid pending OTP can still be verified after all five requests are used. Mobile wrong-code attempts are limited to five for ten minutes; a successful new OTP request resets this attempt counter. An additional route throttle limits verification traffic.
- Server status restores cooldown/daily-limit state across app reloads. No database migration or provider credential change is required. Existing website phone verification code remains unchanged.
- Bulk360 acceptance is checked against https://sms.360.my/developers/v3.0; acceptance does not guarantee handset delivery.
